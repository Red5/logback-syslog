Chapter 3: Appender configuration

The appender is org.red5.logback.syslog.SyslogAppender. Properties are set as child elements in logback.xml, in any order, exactly as with Logback's own appenders. Invalid values do not throw: the appender writes an error to Logback's status system and does not start (see Chapter 8).

Connection

PropertyTypeDefaultDescription
syslogHostStringlocalhostHost name or address of the syslog server. Ignored for UNIX. For TLS this is also the name the server certificate must match.
portint514Server port, 1 to 65535. Ignored for UNIX. Conventional ports are 514 (UDP and TCP) and 6514 (TLS).
protocolenumUDPUDP, TCP, TLS or UNIX. See Chapter 4.
unixSocketPathString/dev/logSocket path for UNIX. The local syslog socket is /dev/log on Linux and /var/run/syslog on macOS.
unixSocketTypeenumDATAGRAMSocket type for UNIX: DATAGRAM (one datagram per message; /dev/log and /var/run/syslog are datagram sockets; Linux and macOS only) or STREAM (newline-terminated messages on a stream connection, e.g. syslog-ng unix-stream()). See Chapter 4.

Message content

PropertyTypeDefaultDescription
facilityStringUSERSyslog facility: KERN, USER, MAIL, DAEMON, AUTH, SYSLOG, LPR, NEWS, UUCP, CRON, AUTHPRIV, FTP or LOCAL0 to LOCAL7. Case-insensitive.
appNameStringnoneProgram name. In RFC 3164 mode it is the tag before the colon (red5:); with rfc5424 it is the APP-NAME field (1 to 48 printable ASCII characters, no spaces).
suffixPatternString[%thread] %logger %msgLogback PatternLayout pattern for the text of each syslog message. Must not be empty. Exception output is never taken from this pattern.
stackTracePatternString%ex{full}Pattern used to render exceptions; each resulting line is sent as its own message. Must not be empty unless throwableExcluded is true.
throwableExcludedbooleanfalseWhen true, exceptions are not sent.
sendLocalNamebooleantrueInclude the local host name in the RFC 3164 header. For UNIX the default is false, because the local socket format has no host name and journald and rsyslog would read it as the tag. Ignored with rfc5424.
sendLocalTimestampbooleantrueInclude a timestamp in the RFC 3164 header. Ignored with rfc5424.
maxMessageLengthint1024; 2048 with rfc5424Maximum size in bytes of one message including its header; at least 128. See Message length.
rfc5424booleanfalseSend RFC 5424 frames instead of RFC 3164. Enables structuredData. See Chapter 5.

TLS

PropertyTypeDefaultDescription
sslTrustStoreStringnonePath of the trust store holding the certificates that may sign the server certificate. JKS and PKCS12 are detected automatically.
sslTrustStorePasswordStringnonePassword of the trust store.
sslKeyStoreStringnonePath of a key store with the client certificate, for servers that require client authentication.
sslKeyStorePasswordStringnonePassword of the key store.
sslVerifyHostnamebooleantrueRequire the server certificate to match syslogHost. Setting this to false is insecure; see Chapter 4.

Delivery

PropertyTypeDefaultDescription
syncbooleanfalseSend from the calling thread instead of through the queue. Not recommended for TCP, TLS or unix sockets, because a slow server then slows the application.
queueSizeint4096Capacity of the in-memory queue between the application and the writer thread. Must be positive.
blockWhenFullbooleanfalseWhen the queue is full: false drops the new event (and counts it); true makes the logging call wait for room.
shutdownTimeoutMslong2000How long stop() waits for queued events to be written. 0 means do not wait.
backlogSizeint1000Messages kept in memory while the server cannot be reached, then replayed in order. 0 disables the backlog.

The queue, backlog and shutdown settings are explained in Chapter 6.

Nested elements

modifier

A modifier changes the text of each message before it is sent. Name the class in the class attribute and set its properties as child elements:

<modifier class="org.red5.syslog.impl.message.modifier.text.PrefixSyslogMessageModifier">
  <prefix>[r5]</prefix>
</modifier>
<modifier class="org.red5.syslog.impl.message.modifier.text.SuffixSyslogMessageModifier">
  <suffix>END</suffix>
</modifier>
<modifier class="org.red5.syslog.impl.message.modifier.escape.HTMLEntityEscapeSyslogMessageModifier"/>

Modifiers run in the order written. With rfc5424 they act on the message text only, not on the header or structured data.

Which modifiers work from XML

PrefixSyslogMessageModifier (property prefix), SuffixSyslogMessageModifier (suffix) and HTMLEntityEscapeSyslogMessageModifier can be configured in XML. The case, checksum, hash, MAC and sequence modifiers need constructor arguments or a configuration object, so they can only be added in code (see Chapter 7). An unknown class name is reported as an error by Logback and ignored; the appender still starts, without that modifier.

structuredData

Adds an RFC 5424 structured data element to every message. It has an effect only when rfc5424 is true; otherwise the appender records a warning. Give an id and any number of entry elements:

<structuredData>
  <id>meta@32473</id>
  <entry><name>app</name><value>live</value></entry>
  <entry><name>site</name><value>eu-west</value></entry>
</structuredData>

The id and the parameter names must be 1 to 32 printable ASCII characters without a space, =, ] or ". Ids must be unique. Parameter values may contain any text; the characters ", \ and ] are escaped as the RFC requires. Use an enterprise number of your own after the @ (the example uses 32473, which RFC 5612 reserves for documentation).

Why not <param>?

Logback's configurator reserves the element name param and ignores attributes on nested components, so the id is a child element and parameters are entry elements.

Accessing the dropped counter

The appender counts events it could not deliver. Read the count in code:

LoggerContext ctx = (LoggerContext) LoggerFactory.getILoggerFactory();
SyslogAppender syslog =
    (SyslogAppender) ctx.getLogger(Logger.ROOT_LOGGER_NAME).getAppender("SYSLOG");
long dropped = syslog.getDroppedCount();
