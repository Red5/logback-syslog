Chapter 4: Transports and TLS

Select the transport with the protocol property.

ProtocolUse it forNotes
UDPA local or trusted-network syslog daemonFast, and nothing is retained if the server is down: UDP gives no delivery feedback. Each message must fit one datagram (65507 bytes at most).
TCPReliable delivery on a trusted networkMessages are LF-delimited. Failed writes go to the backlog and are replayed.
TLSRemote collectors and hosted servicesTCP inside TLS, with host name verification on by default.
UNIXA daemon listening on a unix stream socketStream sockets only; see below.

UDP

The default. Set syslogHost and port. The host name is resolved once and cached for the lifetime of the appender, so a server that moves to a new address needs the appender to be restarted. A message longer than maxMessageLength is split (RFC 3164) or truncated (RFC 5424); the limit is capped at 65507 bytes, and the appender records a warning when it lowers a larger configured value.

TCP

<protocol>TCP</protocol>
<syslogHost>logs.example.com</syslogHost>
<port>514</port>

The connection is opened when the first message is sent and kept open. Connecting is bounded by a 3 second timeout. If the server cannot be reached, messages wait in the backlog and the appender reconnects with a growing delay; see Chapter 6.

Messages are terminated by a line feed in both RFC 3164 and RFC 5424 mode (RFC 6587 non-transparent framing). Octet-counted framing is not implemented. A message that contains line breaks is sent as one syslog message per line, so the framing cannot be corrupted.

TLS

TLS is TCP inside a TLS session. Configure a trust store holding the certificate (or its issuer) of the server:

<protocol>TLS</protocol>
<syslogHost>logs.example.com</syslogHost>
<port>6514</port>
<sslTrustStore>/etc/red5/syslog-truststore.p12</sslTrustStore>
<sslTrustStorePassword>changeit</sslTrustStorePassword>

To create a trust store from a server certificate file:

keytool -importcert -alias syslog -file logs.example.com.crt \
        -keystore syslog-truststore.p12 -storetype PKCS12 -storepass changeit

If the server demands a client certificate, also set sslKeyStore and sslKeyStorePassword.

The stores are read when the appender starts. A store file that does not exist, cannot be read, or does not open with the given password stops the appender from starting; the reason is recorded as an error in Logback's status output (for example File does not exist or it does not refer to a normal file).

Host name verification

The server certificate must contain syslogHost as a subject alternative name (a DNS name, or an IP address when you connect by address). A certificate for a different name is rejected and the connection fails; the failure is reported in Logback's status output (for example No subject alternative DNS name matching logs.example.com found) and the affected messages are backlogged. Server name indication is sent for host names.

Disabling verification

<sslVerifyHostname>false</sslVerifyHostname> accepts any certificate chaining to a trusted issuer for any host name, which allows a man-in-the-middle to read the logs. Use it only for testing, or when the trust store contains nothing but the one server certificate.

Isolation from the JVM's TLS settings

The appender builds its own TLS context from the stores you configure. It does not read or change the JVM-wide javax.net.ssl.* system properties, so it does not interfere with other TLS clients in Red5, and several appenders may use different stores. The handshake is bounded by the same 3 second timeout as connecting.

Trust store required

The appender currently refuses a TLS configuration with neither sslTrustStore nor sslKeyStore. To trust the public certificate authorities (for a hosted service with a publicly issued certificate), point sslTrustStore at the JDK's $JAVA_HOME/lib/security/cacerts with the password changeit.

Unix sockets

<protocol>UNIX</protocol>
<unixSocketPath>/var/run/syslog-ng/syslog.sock</unixSocketPath>

The appender connects with the JDK's unix domain socket support (no native library) and writes one line per message.

Stream sockets only

Java 21 has no unix datagram sockets. Most Linux systems expose /dev/log as a datagram socket (journald, and rsyslog by default), and the appender cannot write to it. It works with a listener that accepts stream connections, such as a syslog-ng unix-stream() source or an rsyslog stream input. For local logging to journald or rsyslog use UDP to 127.0.0.1 or TCP instead.
