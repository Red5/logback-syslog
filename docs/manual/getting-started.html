Chapter 2: Getting started

Adding the jar

The artifact is org.red5:red5-logback-syslog. It is not yet published to a public repository, so build it from source and install it locally:

git clone https://github.com/Red5/logback-syslog.git
cd logback-syslog
mvn -DskipTests install

Then depend on it in your Maven build:

pom.xml
<dependency>
  <groupId>org.red5</groupId>
  <artifactId>red5-logback-syslog</artifactId>
  <version>1.0.0-SNAPSHOT</version>
</dependency>

For a Red5 server, copy target/red5-logback-syslog-1.0.0-SNAPSHOT.jar next to the other logging jars in lib/. Logback and SLF4J are already there.

A first configuration

Add the appender to logback.xml and attach it to the root logger (or to any logger):

logback.xml
<configuration>
  <appender name="SYSLOG" class="org.red5.logback.syslog.SyslogAppender">
    <syslogHost>127.0.0.1</syslogHost>
    <port>5140</port>
    <facility>LOCAL0</facility>
    <appName>red5</appName>
  </appender>

  <root level="INFO">
    <appender-ref ref="SYSLOG"/>
  </root>
</configuration>

This sends RFC 3164 messages over UDP to 127.0.0.1:5140. Every property has a default; only syslogHost normally needs changing. The full list is in Chapter 3.

Checking that messages arrive

The jar contains a small syslog server you can use as a listener. Start it on the same port in another terminal:

java -cp red5-logback-syslog-1.0.0-SNAPSHOT.jar \
     org.red5.syslog.server.SyslogServerMain -h 127.0.0.1 -p 5140 udp

Log something from your application:

Logger log = LoggerFactory.getLogger("org.red5.server.Demo");
log.info("stream started");
log.error("publish failed", new IllegalStateException("no codec"));

The listener shows each message as it arrives. Over the wire the two calls above look like this (the host name is that of the sending machine):

<134>Oct  1 09:17:11 red5host red5: [main] org.red5.server.Demo stream started
<131>Oct  1 09:17:11 red5host red5: [main] org.red5.server.Demo publish failed
<131>Oct  1 09:17:11 red5host red5: java.lang.IllegalStateException: no codec
<131>Oct  1 09:17:11 red5host red5: 	at org.red5.server.Demo.main(Demo.java:12)

The number in angle brackets is the priority: the facility times 8, plus the severity. LOCAL0 is facility 16, so 128, plus 6 for INFO gives 134, and 128 plus 3 for ERROR gives 131. The exception was sent as its own messages, one per line.

If nothing appears

Turn on Logback's status output by adding debug="true" to the root element:

<configuration debug="true">

The appender reports configuration problems there, and does not start if a setting is invalid (for example a port out of range). See Chapter 8 for the messages you may see.

A production-style example

A TLS connection to a remote collector, RFC 5424 output with structured data, and a bounded queue and backlog (each setting is explained in the following chapters):

logback.xml
<appender name="SYSLOG" class="org.red5.logback.syslog.SyslogAppender">
  <syslogHost>logs.example.com</syslogHost>
  <port>6514</port>
  <protocol>TLS</protocol>
  <sslTrustStore>/etc/red5/syslog-truststore.p12</sslTrustStore>
  <sslTrustStorePassword>changeit</sslTrustStorePassword>

  <facility>LOCAL0</facility>
  <rfc5424>true</rfc5424>
  <appName>red5</appName>
  <suffixPattern>%logger{35} %msg</suffixPattern>
  <structuredData>
    <id>origin@32473</id>
    <entry><name>app</name><value>live</value></entry>
  </structuredData>

  <queueSize>4096</queueSize>
  <backlogSize>1000</backlogSize>
</appender>
