Chapter 7: The syslog library

The jar contains the whole syslog4j feature set under org.red5.syslog. You can use it without Logback to send syslog messages from any code, to run a syslog server (for example in tests), or to build a message pipeline with modifiers. The appender itself is a thin layer over this library.

Sending messages

Build a configuration object for the transport, create an instance, and log through it:

import org.red5.syslog.Syslog;
import org.red5.syslog.SyslogIF;
import org.red5.syslog.impl.net.udp.UDPNetSyslogConfig;

UDPNetSyslogConfig config = new UDPNetSyslogConfig();
config.setHost("logs.example.com");
config.setPort(514);
config.setFacility("LOCAL0");
config.setIdent("red5");

SyslogIF syslog = Syslog.createInstance("red5", config);
syslog.info("stream started");
syslog.error("publish failed");
// ...
Syslog.destroyInstance("red5");

The transports are selected by the configuration class:

ClassTransport
org.red5.syslog.impl.net.udp.UDPNetSyslogConfigUDP
org.red5.syslog.impl.net.tcp.TCPNetSyslogConfigTCP
org.red5.syslog.impl.net.tcp.ssl.SSLTCPNetSyslogConfigTLS (setTrustStore, setKeyStore, setSslVerifyHostname)
org.red5.syslog.impl.unix.socket.UnixSocketSyslogConfigUnix socket (setPath; setType: SOCK_DGRAM, the default, or SOCK_STREAM)
org.red5.syslog.impl.net.tcp.pool.PooledTCPNetSyslogConfigTCP with a pool of connections
org.red5.syslog.impl.multiple.MultipleSyslogConfigFan-out to several destinations; each fails independently

The static registry also provides default instances by protocol name, as in syslog4j: Syslog.getInstance("udp") and Syslog.getInstance("tcp") return ready-made instances that you configure through getConfig(). The Logback appender does not use the registry, so the two do not interfere.

Modifiers and structured messages

Message modifiers can be added in code, including those that cannot be configured from XML:

config.addMessageModifier(new PrefixSyslogMessageModifier("[r5]"));
config.addMessageModifier(new SequentialSyslogMessageModifier(new SequentialSyslogMessageModifierConfig()));

The available modifiers are in org.red5.syslog.impl.message.modifier: text (prefix, suffix, case), sequential, checksum, hash, mac and escape. Structured (RFC 5424) messages are built with StructuredSyslogMessage, and PCI-style messages with PCISyslogMessage, both under org.red5.syslog.impl.message.

Running a syslog server

The jar includes UDP, TCP and TLS syslog servers. From the command line:

java -cp red5-logback-syslog-1.0.0-SNAPSHOT.jar \
     org.red5.syslog.server.SyslogServerMain -h 0.0.0.0 -p 5140 -o received.log tcp
OptionMeaning
-h <host>Host or address to bind.
-p <port>Port to bind.
-t <timeout>Socket timeout in milliseconds.
-o <file>Write received messages to this file (overwritten, unless -a).
-aAppend to the file instead of overwriting.
-qDo not print to standard output.

The last argument is the protocol, udp or tcp. In this option set, -h is the host (not help). A matching command-line client sends one message: org.red5.syslog.SyslogMain -h host -p port <protocol> message....

In code, create a server with an event handler:

UDPNetSyslogServerConfig cfg = new UDPNetSyslogServerConfig();
cfg.setHost("0.0.0.0");
cfg.setPort(5140);
cfg.addEventHandler(new SyslogServerSessionlessEventHandlerIF() {
    public void event(SyslogServerIF server, SocketAddress from, SyslogServerEventIF event) {
        System.out.println(event.getHost() + " " + event.getMessage());
    }
    public void exception(SyslogServerIF server, SocketAddress from, Exception e) { e.printStackTrace(); }
    public void initialize(SyslogServerIF server) { }
    public void destroy(SyslogServerIF server) { }
});
SyslogServerIF server = SyslogServer.createThreadedInstance("udp-5140", cfg);
// ...
SyslogServer.destroyInstance("udp-5140");

TCP servers use TCPNetSyslogServerConfig and the session handler SyslogServerSessionEventHandlerIF (with sessionOpened and sessionClosed); TLS servers use SSLTCPNetSyslogServerConfig, which takes a key store and password.

Differences from syslog4j 0.9.46

AreaChange
Packagesorg.productivity.java.syslog4j is now org.red5.syslog; class names are unchanged.
log4jThe log4j appender and back-log handler are not included. Use the Logback appender.
Unix socketsJNA is gone. Datagram sockets (the default type, which /dev/log is) call the C library through java.lang.foreign, used reflectively, on Linux and macOS; stream sockets use the JDK's own support. If datagram sockets are unavailable (for example on Windows) initialize() fails with the reason, and the default unix_syslog and unix_socket instances are not registered. The unix_syslog protocol, which called libc through JNA, now uses the same socket implementation as unix_socket.
Connection poolApache Commons Pool is replaced by a small bounded pool. Only the maximum active connections and the maximum wait are used; the idle, eviction and test settings are accepted and ignored.
TLSEach instance has its own TLS context; the javax.net.ssl.* system properties are never read or changed. Host name verification is on by default (setSslVerifyHostname), and connecting and the handshake are bounded by setConnectTimeoutMillis (default 3000).
DatesJoda-Time is replaced by java.time. StructuredSyslogServerEvent.getDateTime() returns an OffsetDateTime, and RFC 5424 timestamps are printed with at most six fractional digits.
Base64The bundled encoder is replaced by java.util.Base64.
FixesA failing UDP send is retried the configured number of times and then reported; the original loop never ended. Truncation no longer cuts through a multi-byte UTF-8 character.
